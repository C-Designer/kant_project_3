# 실험 B. 청크 크기(100–900) × 오버랩(0·10·20%) × k(4–7)

## 요약

- 오버랩(0·10·20%)은 효과가 없다. 쪽 단위 재현율 0.466 / 0.461 / 0.465.
- 청크 크기는 100–800자가 비슷하고 900자가 약간 높다(Recall 0.70).
- 검색 방식과 k의 효과가 청크 설정보다 크다. 결정은 **보류**(현재 값 900자·오버랩 0 유지).

## 실험 개요

- 날짜: 2026-11-11 · 작성자: @rjqnrll7-cmyk · 관련: `src/config.py`(CHUNK_SIZE=900, CHUNK_OVERLAP=0, K=5)
- 원자료: `data/crag_exp/chunk_overlap/{retrieval,answers}/s<크기>_o<오버랩%>.json` 27개 조합, 표 `rows.json`. 실행 스크립트 `scripts/chunk_overlap_experiment.py`(`retrieve` → `generate` → `report`, 별도 브랜치).
- 질문: `results/questions-2.json` 15문항(9/3/3, 시드 20261105). 방식: naive / hybrid / hybrid_rerank. 색인은 메모리 로컬, 공용 색인 변경 없음.
- 코드 상태: `git_commit` `1fe65c4`, 실험 스크립트는 추적 안 된 파일.

## 가설 (결과 전에 적음)

1. 오버랩 10–20%는 경계에 걸린 근거를 살려 쪽 단위 근거 재현율을 올린다.
2. 청크가 작을수록(100–300) 같은 k에서 재현율이 떨어지고 k를 키우면 일부 회복된다.
3. 청크가 클수록 k=6–7에서 문맥 한도 3,000토큰에 걸려 뒤 청크가 잘린다.
- 기준 조건: 900 / 0% / k=5. "좋아졌다"의 기준: 세 방식 중 두 방식 이상에서 쪽 단위 재현율이 +0.05 이상이고 행동 일치율이 기준보다 낮지 않음. 0.05 미만 차이는 우연.

## 지표

Recall@k·Hit@k는 근거 문서(book_id) 기준. **쪽 단위 근거 재현율**은 골든 근거 그룹 중 (book_id, 쪽)이 같은 청크가 상위 k에 있는 비율. **행동 일치율**은 답변 상태가 `expected_action`과 같은 비율(규칙 비교, 내용의 정확성은 아님). LLM 채점(Faithfulness 등)은 하지 않았다.

## 가설 대조

| 가설 | 결과 | 판정 |
|---|---|---|
| 1. 오버랩이 쪽 단위 재현율을 올린다 | 0.466 / 0.461 / 0.465 (0/10/20%). 기준 대비 +0.05 이상이면서 행동 일치가 낮지 않은 조합은 k=5에서 **방식 하나에서만** 나왔고(naive 10개 조합, hybrid_rerank 800/0%) 두 방식 이상인 조합은 **없음** | **기각** (효과 없음) |
| 2. 작은 청크는 재현율이 낮고 k로 회복 | 100자 Recall 0.625 대 900자 0.700(차 0.075), 쪽 단위 0.467 대 0.500. k 4→7에서 +0.09 | **부분 지지** (100–300은 서로 차이 없음, 900이 높음) |
| 3. 큰 청크는 k=6–7에서 한도에 걸린다 | 모든 조합·k에서 문맥에 들어간 청크 수가 k와 같았다(잘린 청크 **0건**). 입력 토큰 평균은 900자에서 2,866 | **기각** (이 15문항에서는 한도에 안 걸림) |

## 해석·한계

- 이 표본(15문항)에서 **청크 크기 900, 오버랩 0이 나쁘지 않은 선택**이다. 크기를 줄이거나 오버랩을 넣어도 두 방식 이상에서 일관되게 좋아진 조합이 없다.
- 방식 효과(naive < hybrid < hybrid_rerank)와 k 효과(+0.09)가 청크 설정 효과보다 크다.
- 행동 일치율은 0.70–0.73으로 설정과 무관하게 비슷하다. 되묻기·보류 문항(6개)을 모델이 대부분 답변으로 처리하는 경향이 보인다(기준 조건에서 clarify 0.33, abstain 0–0.33, 실험 D 참고).
- 오버랩은 `src/search/chunking.py`가 지원하지 않아 스크립트 안에서 구현했다(앞 조각 본문의 마지막 N글자를 앞에 붙임, 머리줄 40–74자는 크기에 포함). 크기 100에서는 머리줄이 최대 74자라 본문이 26–60자만 남아 **"작은 청크의 한계"와 "머리줄 비중"이 섞여 있다**.

## 실패·이상 기록

- 600자 / 10% / naive 조합에서 답변 생성 오류가 k=4·5·6에서 4건씩, k=7에서 5건, 합계 **17건** 있었다. 이 조합의 행동 일치율(0.60–0.64)은 오류 문항을 뺀 값이라 다른 조합과 같은 분모가 아니다. 다른 조합은 오류 0건. 기록된 오류는 모두 `LLMError: LLM 호출 실패 (model_error)`이고 재실행하지 않았다.
- 평균은 조합 수(27)로 낸 단순 평균이고, 조합마다 15문항·1회 실행이라 개별 조합의 순위는 우열의 근거가 아니다.
- 결정: **보류**. 갱신한 것 없음(`src/config.py` 변경 없음).
