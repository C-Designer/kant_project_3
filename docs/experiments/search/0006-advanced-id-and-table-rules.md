# EXP-0006. Advanced에서 번호 일치 우선과 같은 쪽 표 붙이기가 답할 재료를 늘리는지, 표 청크 소제목은 쓸 수 없는지 확인하고 Basic·Intermediate에 교차 적용한다

- 상태: 완료
- 날짜: 2026-11-09 (5.29~5.35절). 5.36~5.38절은 날짜 없음
- 작성자: @yshzjq
- run_id: 없음 (탐색용 분석 스크립트로 측정, 공식 metrics run이 아님)
- 관련: 이전 실험 EXP-0004, EXP-0005, spec `docs/specs/search.md`, 원본 `search-experiments.md` 5.29~5.38절

> 사후 정리. 수치는 원본 그대로이고 만들거나 반올림한 값은 없다. 원본이 "모델 3명 판정, 참고 수치"라 붙인 판정은 사람 검증이 아니며, "충분"은 LLM이 맞게 답한다는 보증이 아니다. 저장소 코드는 바꾸지 않았다.

## 가설·배경

- 무엇이 문제였나: Advanced에서 번호(영문+숫자+하이픈) 있는 질문의 같은 건 문서가 후보에서 밀리고, 계약 조건 약정 쪽의 기본 무료기간·요율 구간표가 든 표 청크가 최종 5개에 없어 답할 재료가 부족한 문항(AS-DEV19·20·21 등)이 있었다(5.29~5.30절).
- 무엇을 바꾸면 무엇이 좋아질 것이라 보나: 질문의 번호가 든 청크를 먼저 두면, 표 청크를 쪽 단위로 함께 돌려주면 답할 재료가 늘 것이라 봤다.
- 좋아졌다고 판단할 기준: 사전 기준 없음(사후 정리). 원본 기록의 판단을 아래 결정에 적는다.

## 해석·한계

- 결과가 말해주는 것: 번호 일치 우선은 Advanced 두 문항 집합에서 rerank Recall 개발용 +.035, additional +.092이고 쪽+인용문이 바뀐 문항은 개선뿐이다(5.31절). 같은 쪽 표 붙이기로 DEV19·20·21이 충분이 되었고 합계 1000자 상한이 판정을 유지하며 글을 23% 줄인다(4,605 → 3,524자).
- 말해주지 못하는 것: 판정은 개발용 30문항뿐(additional 미판정)이고 사람 검증이 아니다. 5.34절 기준 최종 글이 늘어 answer 쪽 컨텍스트 한도 3000과 맞는지 확인이 필요하다(5.45절: 표 붙이기 시 k=5 최대 2,518, k=7은 1~2건 초과). 반환 글이 바뀌므로 spec과 `source_ids` 검증 약속을 확인해야 한다(5.34절). 5.31절의 소제목 악화 원인은 추정이다. 짧은 표만(400자 이하) 기준은 계약 표 크기를 보고 정한 값이라 판정하지 않았다.
- Intermediate에서 번호 우선이 손해이고 원인은 미확인이다. Basic은 기준이 Hit·모든그룹 1.000인 천장 효과로 이득 확인이 불가능했다(5.36절, 번호 문항 확장검증 9개뿐).
- 우연인지 확인한 방법: 5.31절은 두 문항 집합(개발용·additional) 동시 개선, 5.37절은 두 집합에서 모두 악화로 확인했다. 그 외 통계 검정은 원본에 없음.
