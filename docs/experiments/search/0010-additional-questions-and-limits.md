# EXP-0010. 개발용 질문으로 정한 검색 설정이 추가 질문에서도 유지되는지 확인한다

- 상태: 완료
- 날짜: 2026-11 (원본 기록 기준. 인용한 절 중 날짜가 있는 것은 2026-11-08 ~ 2026-11-09)
- 작성자: @yshzjq
- run_id: 없음 (탐색용 분석 스크립트로 측정, 공식 metrics run이 아님)
- 관련: EXP-0001(임베딩 모델), EXP-0002(청킹), EXP-0003(hybrid 파라미터), spec `docs/specs/search.md`, 원본 `search-experiments.md` 6절·7절·8절(교차 확인에 5.16~5.28절, 5.41~5.44절의 개발용 / additional 쌍을 인용)

> 사후 정리 문서다. 숫자는 원본 그대로이며 만들거나 반올림한 값은 없다. 이 문서가 다룬 절은 담당 범위만이고 다른 절에 있는 additional 값은 위에 적은 절만 인용했다.

## 가설·배경

- 무엇이 문제였나: 청킹·hybrid 설정은 개발용 질문(`S-DEV-*`, `IS-DEV-*`, `AS-DEV*`)으로 골랐다. 개발용 질문에만 맞춘 설정일 수 있다.
- 무엇을 바꾸면 무엇이 좋아질 것이라 보나: 질문 집합을 개발용에서 추가 질문(`additional_questions.json`, `S-FINAL-*`, `AS-ADD*`)으로 바꿔도 설정의 우열이 유지되면 과적합이 아니라고 본다.
- 좋아졌다고 판단할 기준: 사전 기준 없음(사후 정리). 원본 기록의 판단을 아래 결정에 적는다.

## 예시

추가 질문(`additional`)은 개발용 질문으로 정한 설정을 한 번 더 확인하려는 별도 질문 모음이다. 답변하는 질문 말고 되묻기와 보류 질문도 들어 있다.

| 질문 | 기대 동작 |
|---|---|
| `가온루트 우리 건 이제 끝난 건가요?` (S-FINAL-12) | 되묻기(어떤 건인지 모름) |
| `수하인에게 선하증권 발행본이 있다고 합니다. 이 안내만 보고 그 사람이 LA에서 화물을 받을 법적 권한이 있다고 확정해 주세요.` (S-FINAL-23) | 보류(자료로 확정할 수 없음) |
| `반입이 지연될 것 같습니다. 이 절차 안내만으로 하루 늦으면 얼마를 부담하는지 산출해 주세요.` (S-FINAL-30) | 보류 |

이런 문항도 근거 그룹이 있으면 Hit·Recall에 들어간다(근거 그룹이 없는 문항만 제외되며, Basic은 60문항 중 56문항이 근거 그룹을 가진다). 충분 판정에서는 `required_facts`가 보류·되묻기의 근거와 후속 확인이라서 "그것을 뒷받침하는 안내가 청크에 있는가"를 본다.

## 해석·한계

- 결과가 말해주는 것: base의 절대 수준(Hit 0.93~1.00, Recall 0.64~0.71)은 개발용과 비슷해서 개발용 질문에만 맞춘 설정은 아니다(원본 6절). 교차 확인 표에서도 Advanced 표 분리(hybrid·rerank), 본문 1000자, 번호 통째는 두 집합에서 같은 방향이다. 반대로 갈린 것은 naive 표 분리, bge-m3(개발용 +.006, additional -.023), Basic POOL 30(rerank k=10 개발용 +.021, additional -.041, 5.43절)이고 hybrid에서 보인 w 0.4 이득은 rerank에서 사라졌다.
- 말해주지 못하는 것: 방식 순서가 개발용과 뒤집혔다(6절: additional은 naive > hybrid > hybrid_rerank). 차이가 1~2문항 크기라 우연의 범위이고 Basic에서 방식 우열을 말할 근거는 없다. 이번 검증은 base 하나만 쟀으며 "base가 700·1100자보다 낫다"를 새 질문으로 확인한 것은 아니다. 질문이 28~29개라 0.03 이하의 차이는 구별하기 어렵다(7절).
- 조건이 달랐던 점이 결과에 준 영향: 7절 한계. 지표가 문서 단위라 "정답이 든 조각을 찾았는가"는 보지 않으며 겹침·표 행 단위 청킹 같은 조각 수준 개선은 드러나지 않을 수 있다. 청킹 규칙(머리말·꼬리말 제거, 제목·부서 첫 줄)은 Basic 구조 기준이고 Intermediate는 표(44개 문서, 2,671쪽, 열 머리 줄 22종), Advanced는 머리말이 없어 대체 경로로 동작한다. 속도는 이 PC의 CPU 기준이다(원본 7절 작성 당시 PyTorch가 CPU 빌드, 이후 GPU 측정은 각 절에 표시).
- 방식 간 차이가 실험 효과인지 우연인지 확인한 방법: 6절은 "차이가 1~2문항 크기"라 우연으로 판단. 나머지는 두 질문 집합에서 방향이 함께 가는지로 판단했다.

## 결정·후속 작업

- 결정: 보류(원본 기록의 판단). 개발용에서 정한 설정은 additional에서도 크게 어긋나지 않았으나(Hit 0.93~1.00, Recall 0.64~0.71) 방식 우열은 판단 근거가 없다. 원본 6절은 설정 변경을 권하지 않았다.
- 갱신한 것: 없음.
- 미해결(원본 8절): Intermediate 표 처리(5.10절에서 표 한 청크로 확정, 저장소 `chunking.py`에는 미반영), Advanced 청킹(머리말 없는 구조, 표 칸이 줄마다 나뉨), 임베딩 재비교(Basic 이외 데이터셋의 small vs base), 리랭커 원격 코드 모델 4종과 LLM 계열 큰 모델 미시험, `S-DEV-30` / `S-FINAL-30`은 모든 방식이 놓치는 문항(자료에 답이 없는 문항으로 추정, 미확인), `config.py`의 `RERANKER_MODEL`, `RERANK_CANDIDATES`, `HYBRID_FUSION`, 저장되는 색인 확인(`QDRANT_URL` / 로컬 폴더).
