## 가설·배경

- 무엇이 문제였나: 현행 임베딩은 E5 small이다. 더 큰 모델(E5 base·large), 한국어 추가 학습 모델(KoE5), 다른 계열(bge-m3, bge-m3-ko)이 더 잘 찾는지 확인하지 않았다.
- 무엇을 바꾸면 무엇이 좋아질 것이라 보나: 모델을 키우거나 바꾸면 Recall@5가 오를 것으로 봤다. 원본에 명시된 가설 문장은 없다.
- 좋아졌다고 판단할 기준: 사전 기준 없음(사후 정리). 원본 기록의 판단을 아래 결정에 적는다.

## 해석·한계

- 결과가 말해주는 것: E5 small을 이긴 후보가 없다. bge-m3·bge-m3-ko는 hybrid Recall이 0.669~0.670으로 E5 small(0.661)과 구별되지 않는데 색인이 약 7배, 질문 임베딩이 약 6배 느리다. KoE5는 0.587로 가장 낮았다(원인 미확인). 큰 모델이 낫다는 근거는 나오지 않았다.
- 말해주지 못하는 것: "small이 더 정확하다"가 아니라 "큰 모델이 낫다는 증거가 없다"까지만 말할 수 있다. 28~29문항이라 0.03 이하 차이는 구별하기 어렵다. bge-m3의 sparse·multi-vector 기능은 쓰지 않았다(dense만). 입력 한도 8192토큰 모델은 900자 분할이 최적이 아닐 수 있으나 청크 크기는 다시 비교하지 않았다. KoE5·E5 large·bge-m3-ko는 Advanced에서 재지 않았다. Intermediate에서의 임베딩 모델 비교는 하지 않았다.
- 조건이 달랐던 점이 결과에 준 영향: Basic은 문서가 적고 쉬워 방식 사이가 구별되지 않는다(원본 4절). Advanced는 5.21절에서 bge-m3가 개발용 hybrid +.006, additional -.023이라 어느 모델도 두 집합에서 일관되게 E5 small을 이기지 못했다(bge-m3 모든그룹은 .414 / .345로 약간 높음).
- 방식 간 차이가 실험 효과인지 우연인지 확인한 방법: 5.8절 보조 지표로 같은 결론인지 다시 봤다. naive에서 E5 small이 가장 높고(0.923 / 0.857) hybrid에서는 구별되지 않으며(bge-m3-ko가 한 문항 많음) KoE5가 가장 낮다.

## 결정·후속 작업

- 결정: 기각(모델 교체 안 함). E5 small 유지. 크기·한국어 추가 학습·다른 계열을 모두 비교했고 이긴 것이 없으며 속도가 가장 빠르다(원본 5.7절 결론, 5.21절 "Basic 결론과 같음").
- 갱신한 것: 없음. 원본 5.7절에 `embed.py`가 모델 이름에 `e5`가 있으면 접두어를 붙이는 구현과 `tests/test_embed_prefix.py`가 기록돼 있다.
- 다음 실험 또는 Issue: 미측정으로 남은 것은 Intermediate에서의 small vs base(원본 8절), Advanced에서 KoE5·E5 large·bge-m3-ko(원본 5.21절), KURE-v1·Qwen3-Embedding-0.6B(원본 5.7절 표 "측정 안 함").
