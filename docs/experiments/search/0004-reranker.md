## 가설·배경

- 무엇이 문제였나: 리랭커는 hybrid가 뽑은 후보 안에서만 순서를 바꾸므로 후보 수가 성능 상한이고, 리랭커 시간은 후보 수에 비례해 늘어난다(5.6절). 후보 수와 모델이 최적인지 확인이 필요했다.
- 무엇을 바꾸면 무엇이 좋아질 것이라 보나: 후보를 늘리거나 모델을 바꾸면 k=5 Recall이 오를 것이라는 가정을 시험했다.
- 좋아졌다고 판단할 기준: 사전 기준 없음(사후 정리). 원본 기록의 판단을 아래 결정에 적는다. (원본이 쓴 채택 기준은 "k=5 Recall +.03 이상, 그룹충족도 함께 상승"이다. 5.9절)

## 해석·한계

- 결과가 말해주는 것: 후보를 늘려도 문서 단위 지표는 좋아지지 않고(Basic·Advanced) Intermediate는 20 → 100에서 k=5 Recall +.020(채택 기준 +.03 미만)이다. 이긴 모델이 없다. 첫 줄 빼기는 네 곳 모두 ±.015 이내이고 올라간 문항과 내려간 문항이 섞여 노이즈다. GPU는 결과를 바꾸지 않고 시간만 줄였다.
- 원본의 병목 진단: 후보 단계가 아니라 후보 중 k개를 고르는 단계다(5.12·5.44절). Intermediate 문서 단위 모든그룹이 후보 40에서 25/28인데 최종 5개에서는 14/28이다. 단 후보 40과 최종 5의 풀 크기가 달라 같은 조건의 비교는 아니다(원본). Advanced 개발용은 후보 단계가 .552로 늘지 않아 후보 단계(검색 자체)도 한계다(5.22절).
- 말해주지 못하는 것: 28~29문항이라 .02 안팎은 노이즈(5.10절). Basic 5.6절의 "병목은 순위 품질" 서술은 공식 Recall이 OR 대체 후보를 요구하는 점을 반영하지 않아 원본이 보류했다(5.8절).
- 조건이 달랐던 점: 입력 한도 512인 Dongjin-kr은 청크 뒷부분이 잘렸을 수 있어 순수한 모델 성능이 아니다. Qwen3는 변환판 입력 형식이 맞지 않았을 가능성이 있어 모델 한계로 단정하지 않는다. dragonkue가 낮은 이유는 확인하지 못했다.
- 시험하지 못한 것: `jina-reranker-v2/v3`, `gte-multilingual-reranker-base`, `zerank-2`(자동 권한 검사가 막음), `Qwen3-Reranker-4B/8B`·`bge-reranker-v2-gemma`(로딩 방식이 달라 제외).
- 우연인지 확인한 방법: Basic 기준선 .677이 이전 측정과 같아 스크립트를 믿을 만하다고 봤다. 첫 줄 빼기는 데이터 네 곳과 올라간/내려간 문항 수로 비교했다. 그 외 통계 검정은 원본에 없음.
