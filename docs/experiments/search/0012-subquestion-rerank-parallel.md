## 가설·배경

- 무엇이 문제였나: `hybrid_rerank_subq`는 하위 질문마다 후보 전체를 따로 rerank해서 시간이 하위 질문 수에 비례한다(PR #128 본문 기준 Basic 후보 20에서 rerank 평균 1.8초, 후보 50에서 4.0초).
- 무엇을 바꾸면 무엇이 좋아질 것이라 보나: 하위 질문별 rerank를 병렬(스레드)이나 한 번의 `predict`(배치)로 돌리면 시간이 줄 것이다.
- 좋아졌다고 판단할 기준: 사전 기준 없음(사후 정리). 선정 결과는 순차와 같아야 한다.

## 예시

예시 문항은 [README의 S-DEV-08](README.md#예시-문항-s-dev-08)이다. 하위 질문이 2개라서 rerank는 `(하위 질문, 후보 청크)` 쌍을 2 × 20 = 40개 계산한다.

- 순차(현행): 하위 질문 1의 20쌍을 계산하고, 이어서 하위 질문 2의 20쌍을 계산한다.
- 스레드 병렬: 두 계산을 동시에 시작하지만 같은 GPU 하나에서 40쌍을 계산하므로 총 계산량은 같다.
- 배치: 40쌍을 한 번의 `predict` 호출로 보낸다. 계산량은 같고 호출만 줄어든다.

Basic 60문항의 평균 하위 질문 수는 1.93개이고, 이 값이 rerank 시간(평균 1.40초)을 정한다.

## 해석·한계

- 결과가 말해주는 것: 스레드 병렬은 순차와 같은 시간이다(1.42초 대 1.40초). GPU 하나를 나눠 쓰기 때문이다. 배치 8이 가장 빨랐지만 약 6% 줄어든 정도(1.31 대 1.40)라 오차 범위로 본다. 배치를 키울수록 오히려 느려졌다. 선정 결과는 다섯 방식 모두 60문항에서 순차와 같았다.
- 말해주지 못하는 것: CPU 서버에서는 측정하지 않았다. 계산량이 하위 질문 수에 비례하므로 병렬·배치로 줄지 않을 것으로 보이나 확인한 것은 아니다. 배치가 커질수록 느려진 원인(쌍당 입력이 길어서 등)은 확인하지 않았다.
- 조건이 달랐던 점: 후보 20·k=5 한 가지 조건만 쟀다.
- 방식 간 차이가 실험 효과인지 우연인지 확인한 방법: 같은 60문항을 방식마다 한 번씩 돌렸다. 반복 측정은 하지 않았다. 순차를 먼저 돌려 GPU 예열 순서 영향이 있을 수 있다(미확인).
