## 가설·배경

- 무엇이 문제였나: 5.5절에서 Basic hybrid Recall 0.66은 k 때문이 아니라 검색 결과가 기대 문서를 다 담지 못해서이고(k=5의 이론상 최대 0.978), 근거 그룹을 하나 이상 놓치는 문항이 k=5에서 5문항이었다(5.8절). k를 키우면 좋아지는지, 그리고 answer 쪽 문맥 한도 3,000토큰에 들어가는지 알 수 없었다.
- 무엇을 바꾸면 무엇이 좋아질 것이라 보나: k를 늘리면 Recall과 모든그룹이 오르되 한도 3000에서 잘릴 것이라는 가설을 세 난이도에서 쟀다.
- 좋아졌다고 판단할 기준: 사전 기준 없음(사후 정리). 원본 기록의 판단을 아래 결정에 적는다.

## 결과

Recall은 공식(문서 단위), 모든그룹은 모든 근거 그룹을 문서 단위로 채운 문항 비율, 쪽+인용문은 지정 쪽까지 맞춘 보조 지표다. 값은 개발용 / additional.

### 검색: hybrid_rerank k 비교

| 난이도 | k=5 | k=7 | k=10 |
|---|---|---|---|
| Basic Recall | .677 / .638 | .729 / .701 | .790 / .807 |
| Basic 문서 모든그룹 | .857 / .714 | .929 / .750 | .929 / .821 |
| Basic 쪽+인용문 모든그룹 | .357 / .500 | .464 / .500 | .500 / .571 |
| Intermediate Recall | .798 / .764 | .812 / .802 | .865 / .846 |
| Intermediate 문서 모든그룹 | .500 / .500 | .500 / .571 | .643 / .679 |
| Advanced Recall | .756 / .626 | .782 / .652 | .799 / .678 |
| Advanced 문서 모든그룹 | .448 / .310 | .483 / .310 | .517 / .345 |

근거: 5.46절(Basic), 5.47절(Intermediate), 5.48절(Advanced). Basic k=20 Recall은 .912 / .913(5.39절), Intermediate k=20 .900 / .896(5.40절).

### 검색: Basic 기준 naive·hybrid (5.5절, 개발용 28문항)

| k | naive Recall | hybrid Recall | hybrid Hit | Recall 이론상 최대 |
|---|---|---|---|---|
| 3 | 0.491 | 0.504 | 0.893 | 0.908 |
| 5 | 0.651 | 0.661 | 1.000 | 0.978 |
| 8 | 0.706 | 0.690 | 1.000 | 1.000 |
| 10 | 0.744 | 0.756 | 1.000 | 1.000 |

근거: 5.5절. 5.46·5.47절에서 같은 k의 세 방식 차이는 .01~.07 수준으로 작고 일관되지 않다(Intermediate는 hybrid_rerank가 k=10에서 가장 높다).

### 운영 지표: 3000토큰 한도

| 난이도 | k=7 | k=10 |
|---|---|---|
| Basic (청크 평균 299·최대 450토큰) | 최대 2,973, 초과 0건 | 문항 약 1/2~3/4에서 마지막 1~2개가 빠짐, 평균 8.4~9.5개 들어감 |
| Intermediate (평균 285·최대 524) | 최대 2,330 이하, 초과 0건 | additional 최대 3,197, 초과는 hybrid 4건·hybrid_rerank 2건 |
| Advanced (평균 202·최대 524), 표 붙이기 없음 | 최대 2,910, 초과 0건 | 개발용 hybrid_rerank 8/29, additional 5/29가 초과(최대 4,124) |

근거: 5.45·5.46·5.47절. k=5는 세 난이도 모두 안전하다. 모델 호출 입력·출력 토큰, 응답 시간, 오류율, 비용은 없음: 탐색용 스크립트라 측정하지 않음. Advanced에 같은 쪽 표 붙이기(합계 1000자)를 쓰면 k=7에서 1~2건 초과(최대 3,359), k=10은 18~20/29 초과(최대 4,573)이고 3000을 넘기 시작하는 k는 10이다(5.45·5.40절).

## 해석·한계

- 결과가 말해주는 것: 세 난이도 모두 k를 늘리면 Recall이 같거나 오른다. 한도 3000 안에서 Basic·Advanced(표 붙이기 없음)는 k=7까지, Intermediate는 k=10까지 거의 잘림 없이 들어간다. Basic은 k=5 → 7에서 Recall +.05~.06, Advanced는 개발용 +.026·additional +.017로 더 작다(5.39·5.40절).
- 5.5절: 3 → 5가 가장 큰 도약(Recall +0.15)이고 k=5가 곡선의 무릎이다. 5.5절의 같은 문서 청크 분석에서 k=10의 2번째 이후 청크 153개 중 정답 근거 쪽은 13개(8%)뿐이었다. 근거 밖의 쪽이 답변에 도움이 될지 잡음이 될지는 이 지표로 알 수 없다고 원본이 적었다.
- 말해주지 못하는 것: 28~29문항 규모라 작은 차이는 노이즈 가능. 토큰은 글자÷2+1 근사다. 답변 품질과 정확한 생성 모델 토큰 수는 미측정. Advanced의 "최대 524, 상위 7개 합 3668, 상위 10개 합 5240"이 Intermediate와 같은 값인 이유(우연인지 청크 길이 상한인지)는 확인하지 못했다(5.45절).
- 조건이 달랐던 점: Intermediate k=10 초과 건수는 방식마다 다르다. 개발용 hybrid_rerank는 0건이다(5.47절).
- 우연 여부 확인: 5.5절의 Basic 기준값은 이후 측정(.661, .677 등)과 일치했다. 별도 검정은 원본에 없음.
