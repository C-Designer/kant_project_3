# EXP-0009. 하위 질문마다 따로 rerank한 순위를 번갈아 채워 최종 k개를 고른다 (hybrid_rerank_subq)

- 상태: 완료
- 날짜: 2026-11-10 ~ 2026-11-11 (원본 5.59~5.64절)
- 작성자: @yshzjq
- run_id: 없음 (탐색용 분석 스크립트로 측정, 공식 metrics run이 아님)
- 관련: 이전 EXP-0007, EXP-0008, Issue #125, PR #126(기능 추가), PR #128(후보 50 → 20), spec `docs/specs/search.md`, 원본 `search-experiments.md` 5.59~5.64절·`issue-draft-subquestion-alternating.md`

> 사후 정리다. 숫자는 원본 그대로이며 모두 "잠정"이다. 판정은 EXP-0007의 (나) 종류(gpt-6-luna 단일 판정, 선정된 k개 청크만 보고 충분/부분/불충분)이고 1~2문항 차이는 노이즈다.

## 가설·배경

- 무엇이 문제였나: 질문 전체 하나로 rerank하면 첫 물음의 청크가 상위를 채워 곁가지 물음의 근거가 밀린다(EXP-0008). 예: S-DEV-05에서 마감 청크 SB11 p1은 1위, 순중량 규칙 SB09 p3은 후보 22위·rerank 34위로 k=5에 못 들어와 "불충분".
- 무엇을 바꾸면 무엇이 좋아질 것이라 보나: 하위 질문(LLM이 질문 글만 보고 최대 4개) 마다 후보 50개를 따로 rerank해 순위 목록을 만들고 1위, 2위, ...를 번갈아 담으면(중복은 건너뜀) 하위 질문마다 몫이 보장되어 충분 문항이 늘 것이다.
- 좋아졌다고 판단할 기준: 사전 기준(하위 질문별 시험을 돌리기 직전에 정함): k=5에서 같은 후보의 기존 rerank 대비 충분 +2문항 이상, 1문항 이하는 노이즈. 후속 시도(5.61·5.62·5.64절)도 같은 기준을 썼다.

## 예시

예시 문항은 [README의 S-DEV-08](README.md#예시-문항-s-dev-08)이다. 하위 질문 2개 각각으로 후보 전체를 따로 rerank해 두 줄을 만든다.

| 순위 | 줄 1: 초안 승인만으로 적재 완료라 말해도 되나 | 줄 2: 실제 적재는 무엇으로 확인하나 |
|---|---|---|
| 1 | SB15-p4-c1 (.9996) | SB06-p12-c1 (.9552) |
| 2 | SB05-p3-c1 (.9977) | SB06-p8-c1 (.9445) |
| 3 | SB12-p4-c1 (.9925) | SB12-p3-c1 (.9393) |
| 4 | SB15-p16-c1 (.9924) | SB04-p21-c1 (.9325) |
| 5 | SB14-p13-c1 (.9911) | SB06-p13-c2 (.9036) |

번갈아 담기는 줄 1의 1위, 줄 2의 1위, 줄 1의 2위, ... 순서로 중복을 건너뛰며 k개를 채운다(점수는 줄끼리 비교하지 않고 순위만 쓴다). k=5이면 `SB15-p4-c1`, `SB06-p12-c1`, `SB05-p3-c1`, `SB06-p8-c1`, `SB12-p4-c1`이다. 질문 하나로 rerank한 k=5(SB15-p4-c1, SB05-p3-c1, SB12-p12-c1, SB05-p23-c1, SB06-p8-c1)는 선하증권 서류 이야기에 치우치는 반면, 번갈아 담기는 두 번째 물음("실제 적재 확인", SB06 운항안내팀 쪽)의 몫을 보장한다. 다만 두 선정 모두 골든 quote가 적힌 SB10 3쪽과 SB06 1쪽은 담지 못했다.

## 질문 선택·실행 명령

- 질문 목록: 세 데이터셋 각 60문항, k=5·10(Basic은 7 포함). Basic은 하위 질문 개수 1개 17·2개 24·3개 13·4개 2(근거 그룹 있는 56문항 기준). Intermediate·Advanced는 2개 이상 50문항. 시드 원본에 없음.
- 정답·근거는 선정에 안 쓰고 채점에만 썼다: 예.
- 스크립트: `basic/basic_subsel_test.py`, `basic_subsel_cand_cover.py`, `subsel_ia/subsel_inter_adv.py`, `subsel_cand_quota.py`, `split_v2.py`, `subsel_v2_rrf.py`, `subsel_docscope.py`, `subsel_channel.py`, `subsel_nsweep.py` 등. 실행 명령 원문은 원본에 없음. GPU는 `uv run --with torch+cu132` 임시 덮어쓰기.

## 결과

### 검색·판정: 충분 문항 수 (60 중, 근거 5.59절)

| 데이터셋 | 선정 | k=5 | k=10 |
|---|---|---|---|
| Basic | 기준 hybrid_rerank(POOL 20) | 46 | 50 |
| Basic | S + rerank(전체) / S + Jev / **S + 번갈아** | 46 / 50 / **53** | 49 / 54 / **60** |
| Basic | O + rerank(전체) / O + Jev / **O + 번갈아** | 46 / 49 / **55** | 51 / 54 / **59** |
| Intermediate | 기준 / S 번갈아 / **O 번갈아** | 42 / 43 / **44** | 45 / 45 / **47** |
| Advanced | 기준 / S 번갈아 / **O 번갈아** | 35 / 40 / **42** | 39 / 43 / **43** |

Basic k=7: 기준 47, S 번갈아 59, O 번갈아 56. 같은 후보 rerank 대비 k=5 이득: Basic +7~9, Advanced +8~10(S rerank 32, O rerank 32), Intermediate +1~2. Intermediate 불충분 8 → 2·부분 10 → 14, Advanced 불충분 6 → 0·부분 19 → 18. Advanced(근거 그룹 있는 문항) 공식 Recall 현행 k=5 .723·k=10 .797 → O 번갈아 .803·.848, 쪽+인용문 모든그룹 .293·.310 → .379·.448(`issue-draft-subquestion-alternating.md`). Recall·쪽+인용문은 Basic만 5.58절 표로 확인했고 Intermediate·Advanced는 원본 본문에서 재지 않았다고 적었다.

### 운영 지표

지연(`issue-draft-subquestion-alternating.md`, Advanced 60문항, GPU, 메모리 Qdrant, 하위 질문 만들기 제외, 후보 50): `hybrid_rerank` 평균 1.52초(중앙값 1.63)에 비해 번갈아(O) 평균 9.59초(중앙값 10.76, 최대 18.52). 하위 질문 만들기를 더하면 중앙값 약 14초(추정). Basic·Intermediate는 이 지연을 재지 않았다. 오류율·답변 품질(Faithfulness 등): 없음, 탐색용 스크립트라 측정하지 않음.

## 해석·한계

- 결과가 말해주는 것: Basic·Advanced에서 번갈아 선정은 사전 기준(k=5 충분 +2 이상)을 넉넉히 넘고 Intermediate는 경계(+1~2)다. Basic은 Jev(질문당 약 $0.0017·외부 API)보다 같은 k에서 높았다. 후보 50 안에 근거가 이미 있어(문서 모든그룹 H·S·O 1.000/1.000, 5.59절) 병목은 선정이라는 해석을 뒷받침한다. 5.60~5.63의 변형(몫 보장, v2 프롬프트, 순위 RRF, 문서 안 재검색, 채널 보존)은 모두 이득이 없어 채택하지 않았다. 순위 RRF가 번갈아보다 낮은 이유는 "추정(미확인)".
- 말해주지 못하는 것: 같은 문항 집합에서 만든 방식이라 새 문항 일반화 미확인. 판정 LLM 1회(Basic k=10 60/60은 청크를 직접 열어 확인 안 함). 분해가 흔들려 ±1~2문항은 분해 흔들림도 포함한다. Intermediate·Advanced는 "대충" 조건이라 5.25~5.35의 확정 설정 결과와 직접 비교 불가. 13번 이후 문항에는 `forbidden_claims`가 없어 오답 위험 청크 수는 신뢰하기 어렵다.
- 조건이 달랐던 점: 후보 20 대 50은 Basic k=5만 쟀고 Intermediate·Advanced·k=10은 미측정이다. 후보 밖으로 밀리는 근거가 많은 Intermediate·Advanced에서는 더 불리할 수 있다(추정, 미측정).
- 5.64절 trade-off: 후보 20은 충분 −2(사전 기준 "−2 초과면 안 줄임"의 경계), 후보 안 쪽+인용문 −.30(.893 → .589)이라 원본 판단은 "보수적으로는 50 유지가 안전, 속도 이득은 약 절반"이었다.
