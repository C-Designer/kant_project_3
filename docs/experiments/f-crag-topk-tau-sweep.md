# 실험 F. CRAG top-k × 필터 τ × 검색 방식 (development 30문항)

## 요약

- 재현율을 올리는 가장 확실한 방법은 k를 키우는 것이다(k 5 → 10에서 naive +0.24, hybrid_rerank +0.17).
- 필터 τ가 더하는 이득은 95% 신뢰구간이 0을 포함해 확신할 수 없다.
- k=10에서는 문맥의 절반 이상이 한도 3,000토큰에 걸린다. 결정은 **보류**.

## 실험 개요

- 날짜: 2026-11-10–11 · 산출물: `data/crag_exp/jev/crag-sweep-development.md`(전체 165행), `crag-metrics-development.json`, 시각화 `crag-report-development.html`. 재생성: `uv run python data/crag_exp/crag_report.py`(저장된 기록만 읽음).
- 설계: k 5·7·8·9·10 × naive/hybrid/hybrid_rerank × 필터 수치 τ 11단계(0, 0.1, … 0.9, 0.95) = 165조건. Jev `evidence_en` 점수가 τ 미만이면 청크를 버리고, 문맥에서 걸러진 비율이 큰 질문은 질문을 다시 써서 재검색한다. 재작성 모델 `gpt-6-luna`.
- 수집: `jev_research.py collect <k>`, `jev_pool.py collect`. 통계: 부트스트랩 10,000회(시드 20261111), 노이즈 200회.
- 기준선: k=5, τ=0. 지표 "재현율"은 골든 근거 그룹 재현율(모든 그룹 충족과 구분). 문맥 한도 3,000토큰 적용 후 값(`한도 적용 후`)도 따로 본다.
- 무결성 점검: 누락 쌍 0, 접두 위반 0, 재작성 불일치 0. 같은 (질문, 청크) 쌍 27개가 두 번 채점돼 점수가 다른 문제가 있어(최대 차 0.15) **k=10 실행의 점수로 통일**했다.

## 결과 1 — k의 효과 (τ = 0, 필터 없음, 재현율 / 평균 문맥 토큰)

| 방식 | k=5 | k=7 | k=8 | k=9 | k=10 |
|---|---|---|---|---|---|
| naive | 0.30 / 1,508 | 0.40 / 2,116 | 0.46 / 2,424 | 0.49 / 2,721 | 0.55 / 3,021 |
| hybrid | 0.49 / 1,529 | 0.52 / 2,114 | 0.52 / 2,407 | 0.52 / 2,707 | 0.52 / 3,014 |
| hybrid_rerank | 0.51 / 1,589 | 0.64 / 2,223 | 0.64 / 2,526 | 0.68 / 2,819 | 0.68 / 3,103 |

k=10에서 문맥 토큰 평균이 한도 3,000에 닿아 `한도 초과 문맥`(한도 때문에 잘린 문맥)이 30개 중 naive 16건, hybrid 15건, hybrid_rerank 19건(모두 τ=0)으로 늘어난다. k=9에서는 1 / 3 / 7건이다. **k만 키워도 기준선 대비 이득이 가장 크다**(k=10에서 naive +0.24, hybrid_rerank +0.17. hybrid는 +0.03에 그친다).

## 결과 2 — 필터 τ의 효과 (k=5, 재현율 최초 → 필터+재검색)

| τ | naive | hybrid | hybrid_rerank |
|---|---|---|---|
| 0.0 (기준) | 0.30 | 0.49 | 0.51 |
| 0.3 | 0.30 | 0.47 | 0.51 |
| 0.5 | 0.30 | 0.47 | 0.51 |
| 0.8 ★ | 0.34 | 0.50 | 0.53 |
| 0.9 | 0.32 | 0.49 | 0.52 |
| 0.95 | 0.28 | 0.45 | 0.47 |

(★ 가장 좋은 τ = 0.8. "필터만"은 0.8에서 naive 0.30, hybrid 0.39, hybrid_rerank 0.42로 **내려간다** — 필터가 근거를 잃고, 재검색이 이를 복구하는 구조.)

## 결과 3 — 방식별 최적 조합 (제한 없이 고른 최적, 모두 k=10)

| 방식 | 최적 (k, τ) | 재현율(최종) | 한도 적용 후 | 필터만 | 재검색 문맥 | 평균 최종 청크 | 평균 토큰 | 기준선 대비 (승/패) |
|---|---|---|---|---|---|---|---|---|
| naive | k10, τ=0 (필터 없음) | 0.55 | 0.53 | 0.55 | 0/30 | 10.0 | 3,021 | +0.24 (9/0) |
| hybrid | k10, τ=0.8 | 0.58 | 0.58 | 0.43 | 26/30 | 7.0 | 2,148 | +0.08 (6/4) |
| hybrid_rerank | k10, τ=0.7 | 0.74 | 0.68 | 0.59 | 19/30 | 8.3 | 2,604 | +0.22 (10/1) |

방식 간 비교(부트스트랩 95% 신뢰구간): hybrid_rerank − hybrid는 k≥7에서 +0.13–0.16(CI가 0을 넘지 않음), hybrid_rerank − naive는 모든 k에서 +0.13–0.24(0 초과). hybrid − naive는 k=5에서만 유의(+0.19).

필터가 k를 고정한 상태에서 더하는 이득의 95% 신뢰구간(`max_filter_effect`, 방식별 최대 효과 조건): naive [0.00, 0.11], hybrid [−0.10, +0.23], hybrid_rerank [−0.07, +0.19]. **hybrid·hybrid_rerank는 0을 포함하고 naive도 하한이 0이다.** 한 질문을 빼고 τ를 고르면(LOO) 이득이 대부분 0 이하(−0.12–+0.05)다.

후보 풀 상한(`pool`): 후보 20개 중 어느 한 방식이라도 근거를 찾는 상한(ceiling_union) 0.80, 리랭커 후 0.75. 리랭커 중앙 처리 시간 28.8초(CPU).

## 해석·한계

- **재현율을 올리는 가장 확실한 방법은 k를 키우는 것**이고, 필터 τ는 신뢰구간이 0을 포함해 이득을 확신할 수 없다. 최적 τ(0.7–0.8)는 한 질문을 빼면 바뀐다.
- 필터는 "근거 쪽 최종 비중"(0.09 → 0.14–0.25)을 올리고 "그 밖" 비중(0.39 → 0.24–0.33)을 줄이지만 재현율은 그대로이거나 내려간다. 즉 **문맥이 깨끗해지는 대신 근거 하나를 더 잃는 거래**다. 이를 재검색이 일부 메운다(재검색 문맥이 τ=0.8에서 21–26/30, 즉 비용 급증).
- 한도 3,000토큰 때문에 k=9–10의 이득이 일부 잘린다(한도 적용 후 값이 낮음).
- 질문 30개이고 개발용(development) 질문만 썼다. 최종(final) 질문으로 검증하지 않았다.
- 결정: **보류**. 갱신한 것 없음. 후속: 최종 질문 검증, 필터와 k 상향의 결합(k=7–8 + τ 낮게), 답변 품질(Faithfulness 등) 연결.
