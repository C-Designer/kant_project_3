# 실험 D. Corrective RAG(LLM 평가) 대 기본 파이프라인

## 요약

- 문맥 정밀도가 약 2.2배(0.13 → 0.29)로 오르고 Recall은 거의 그대로다.
- 행동 일치율이 0.69 → 0.78로 올랐는데 거의 보류 문항에서 나왔다(9건 중 1건 → 5건).
- 대가는 토큰이다(입력 +65%, 출력 +117%). 15문항 1회라 결정은 **보류**.

## 실험 개요

- 날짜: 2026-11-10–11 · 관련: 코드 `src/answer/corrective.py`, `prompts/grade.md`, `prompts/rewrite.md`(별도 브랜치, 아직 main 아님)
- 무엇을 바꿨나: 검색한 청크를 LLM이 질문과 관련 있는지 평가(correct / ambiguous / incorrect)해 걸러내고, 부족하면 질문을 다시 써서 재검색한다. 기본 파이프라인(baseline)과 같은 15문항·같은 3방식으로 비교.
- run_id: 기본 `20261110-172517-basic-remote`(k=5), CRAG `20261110-204642-crag`(k=5). 같은 방식으로 k=6–10 실행도 있다: `basic-k6`–`basic-k10`, `crag-k6`–`crag-k10`, 그리고 재실행 `crag-k8`(`013110`), `basic-k9`(`014835`), `crag-k9`(`015950`). **k=5 이외는 이 문서에서 집계하지 않았다.**
- 질문: `results/questions-2.json` 15문항(9/3/3, 시드 20261105). 코드 상태: 기본 `35b2faf`(clean), CRAG `2f1353b`(**dirty**).
- 지표는 규칙 기반(행동 일치율, 근거 문서·쪽 재현율, 정밀도). LLM 답변 채점은 하지 않았다.

## 해석·한계

- **정밀도가 약 2.2배**(0.13 → 0.29)로 오르고 Recall·쪽 Recall은 거의 그대로다. 평가가 쓸데없는 청크를 걸러내고 근거는 버리지 않았다는 뜻이다(naive 문서 Recall만 0.67 → 0.63).
- 행동 일치 개선(0.69 → 0.78)은 거의 **보류 문항**에서 나왔다(0.11 → 0.56). hybrid_rerank 한 방식의 +0.20이 가장 크다. 보류 3문항 × 방식 3개 = 9건 중 4건 차이라 표본이 작다.
- 대가: 평가·재작성 LLM 호출로 입력 토큰 +65%, 출력 +117%. 응답 시간은 naive·hybrid에서 약 2배, hybrid_rerank는 리랭커가 지배해 오히려 짧아 보이는데(61 → 49초) 실행 시각에 CPU 부하가 달라서 **시간 비교는 신뢰하지 않는다**.
- CRAG 실행은 `git_dirty: true`라 코드 상태가 완전히 재현되지는 않는다.
- 결정: **보류**(15문항 1회, LLM 평가기 판정 자체를 사람이 검증하지 않음). 후속: F의 Jev 평가기 결과와 합쳐 판단.
