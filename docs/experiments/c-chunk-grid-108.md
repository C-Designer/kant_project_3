# 실험 C. 청크 크기 × 오버랩 × k × 검색 방식 격자 108조건 (EXP-0002)

## 요약

- k를 4 → 7로 늘리면 Recall이 +0.082 오른다. Faithfulness는 거의 그대로다.
- 청크 크기(100–300자)와 오버랩(10–30%)은 Recall·Faithfulness를 뚜렷이 바꾸지 않는다.
- hybrid_rerank가 Recall은 가장 높지만(0.688) CPU에서 응답이 약 4배 느리다. 결정은 **보류**.

## 실험 개요

- 날짜: 2026-11-12 · 작성자: @rjqnrll7-cmyk · run_id: `20261112-002038-chunk-grid`
- 원문: 별도 브랜치의 `docs/experiments/0002-chunk-size-overlap-k-search-grid.md`(108조건 전체 표 포함). 원자료 `data/chunk_exp/`(저장소 밖).
- B와의 차이: 청크 크기를 **100/200/300**으로 좁히고 오버랩을 **10/20/30%**로, 실험 전용 청커(글자 창, 문장 경계 무시, 머리줄 매 청크에 붙임)를 쓰며 **Faithfulness를 LLM으로 3회 채점**했다. B의 청커와 달라 두 실험의 청크 수가 다르다.
- 질문: 기본 15문항. 방식: e5(naive) / hybrid / hybrid_rerank. 생성·평가 `gpt-6-luna`, 문맥 한도 3,000, 프롬프트 v1.
- 검증: 조건 108개, 질문×조건 1,620행, 채점 1,620행, **오류 0건**, 해당 없음 16건(평균에서 제외), 평가 불가 0건.
- 비용: 생성 $0.5865 + 채점 $3.2253 = **$3.8119**(단가는 사용자 제공 가정: 입력 $0.1, 출력 $0.5 / 100만 토큰). 채점이 비용의 85%.

## 가설 (결과 전에 적음)

H1 청크가 클수록 Recall↑·비용↑ / H2 k가 클수록 Recall↑, Faithfulness 거의 불변 / H3 Recall은 hybrid_rerank ≥ hybrid ≥ e5, 응답 시간은 반대 / H4 오버랩 효과는 작다. 판정 기준: 평균 차이 0.05 이상이면 "차이 있음".

## 해석·한계

- k를 늘리면 근거 문서를 더 찾고(+0.082) 토큰·비용은 늘지만 Faithfulness는 거의 그대로다.
- 100–300자와 오버랩 10–30% 범위에서는 Recall·Faithfulness가 뚜렷이 바뀌지 않았다(B와 일치).
- Faithfulness는 정답 여부가 아니다. 골든의 필수 사실이 빠진 답변도 0.9–1.0일 수 있다(사례 1·5). Judge 4항목(사실·조건·근거·판단)은 하지 않았다.
- 근거 문서가 7개인 문항(S-FINAL-06)은 k=4–6에서 Recall 상한이 낮아 평균을 끌어내린다.
- 청커 한계: 문장 중간에서 시작·끝나는 청크, 머리줄(74–80자)이 매 청크에 붙어 100자 조건의 실제 청크는 평균 약 147자.
- 지연: 이 PC는 GPU가 없고(CPU 6스레드), 검색 지연은 (색인, 방식, 질문)마다 1번 잰 값을 k=4–7에 공유했다. 다른 장비의 절대값과 비교하지 않는다.

## 결정·후속

- 결정: **보류**(Faithfulness 차이가 기준 미만이고 15문항 1회 실행). 갱신한 것 없음.
- 다음: 조건을 좁혀(200자·20%, hybrid 대 hybrid_rerank, k=5 대 7) 25문항으로 반복, Judge 4항목 채점, 문장 경계를 맞춘 청커 비교.
- 실패·이상: 시험 실행(pilot)에서 리랭커 첫 호출에 모델 적재 시간(약 17초)이 섞여 결과를 버리고 모델을 먼저 불러둔 뒤 본 실행. 채점 프로세스를 한 번 중단·재시작했으나 중복·누락 없음. 사람이 점수를 고친 것 없음.
