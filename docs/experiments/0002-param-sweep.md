## 가설·배경

- 무엇이 문제였나 (이전 결과, 실패 사례의 `question_id`): EXP-0001에서 Hit@5는 변별력이 없고(전 실험 1.00), Recall은 질문 구성에 좌우된다. 청킹·`k`·문맥 한도가 검색·답변 품질과 비용(시간·토큰)에 얼마나 민감한지 값을 바꿔 본 적이 없다. 실패 사례 `question_id`는 없음(아직 실행 전).
- 무엇을 바꾸면 무엇이 좋아질 것이라 보나:
  1. `chunk_size`를 줄이면 한 청크가 한 사실에 가까워져 Recall은 오르지만 `k`개 문맥에 들어가는 정보량이 줄어 Faithfulness·사실은 내릴 수 있다. 늘리면 반대다.
  2. `overlap`을 두면 경계에 걸친 근거를 덜 놓쳐 Recall이 오르지만 같은 내용이 중복돼 입력 토큰이 는다.
  3. `topK`를 키우면 Recall은 오르고 입력 토큰·응답 시간도 는다. 줄이면 반대다.
  4. `context_size`(문맥 토큰 한도)는 기준(3000)에서 이미 안 잘린다(실측 최대 1,857). **낮출 때만** 문맥이 잘려 품질이 떨어질 것이고, 올려도 변화가 없을 것이다.
  5. 리랭커 후보 수는 EXP-0001(E3→E4)에서 50→20이 품질 변화 없이 시간을 줄였다. 10까지 줄여도 같은지 본다.
- 좋아졌다고 판단할 기준 (결과를 보기 **전에** 적는다. 아래는 초안이며 리드 확인 후 확정한다):
  - **검색 지표(Hit@k·Recall@k)는 같은 색인·질문이면 결정적**이다. 기준 설정 대비 Recall이 0.05 이상 달라지면 효과가 있다고 본다.
  - **Faithfulness·시간은 잡음이 있다.** 기준 설정을 3번 반복해 얻은 범위(최소~최대)를 잡음 폭으로 두고, 그 폭 밖으로 벗어난 차이만 효과로 본다. 폭 안의 차이는 "차이 없음"으로 적는다.
  - **비용:** 검색 단계 시간이 기준 대비 20% 이상, 입력 토큰이 10% 이상 달라지면 의미 있는 변화로 본다.
  - 조건·근거·판단(Judge)은 이번 실험의 측정 대상이 아니다. 사실·조건·근거·판단 점수는 만들지 않는다.

## 실험 환경·자원 제한

설정끼리 서로 영향을 주지 않게 독립 환경에서 병렬로 돌린다. **확정**은 리드가 정한 것, **제안**은 아직 리드 확인 전이다.

| 항목 | 값 | 상태 |
|---|---|---|
| 호스트 | Apple M5 Max, 18코어, 64GB | 확인 |
| 격리 단위 | Docker 컨테이너 하나가 변수 하나(설정 2개를 순서대로). CPU·메모리 제한을 둔다 | 확정 |
| 병렬도 | 컨테이너 5개(변수당 1개). 기준 설정은 시작 전에 따로 먼저 돌린다 | 확정 (2026-11-12) |
| 컨테이너당 자원 | `--cpus=3`, 메모리 6GB, `OMP_NUM_THREADS=3`·torch 스레드 3. 합계 15코어·30GB로 호스트에 3코어·34GB를 남긴다 | 제안 |

**Docker는 Linux VM이라 호스트 GPU(MPS)를 못 쓴다.** 로컬에서 잰 값(20쌍 리랭크): MPS **0.33초**, CPU 3스레드 **2.65초**(약 8배). 이 측정은 청크 약 350자 가짜 문장이라 실제 900자 청크는 더 느릴 수 있다. 따라서:

- 컨테이너에서 잰 `hybrid_rerank` 응답 시간은 **호스트 실행(EXP-0001, 지난 비교표)의 절대값과 비교하지 않는다.** 설정 사이의 상대 차이만 본다.
- 기준 설정은 같은 컨테이너 환경에서 다시 돌려 기준으로 삼는다(호스트 결과를 기준으로 쓰지 않는다).
- 프로세스 메모리(로컬 측정): MPS 실행에서 임베딩+리랭커 합쳐 약 1.4GB, CPU 리랭커만 약 2.3GB. 컨테이너 한도 6GB는 이를 근거로 한 여유이며, 실제 사용량은 컨테이너에서 재서 고친다.

### latency 측정 (2026-11-12 확정)

병렬 실행에서는 로컬 연산(CPU·메모리 대역폭)과 LLM API 호출(동시 요청 대기·한도)이 서로 간섭해 응답 시간이 흔들린다. 그래서 둘로 나눠 잰다.

1. **검색 단계 시간:** LLM 없이 질문 15개 × 방식 × 설정을 **순차로 따로 돌려** 잰다(비용 없음). 설정 간 비교는 이 값의 중앙값으로 한다.
2. **생성 시간·전체 응답 시간:** 병렬 실행에서 나온 값. 참고용이며 출력 토큰 수와 함께 본다(생성 시간은 대체로 출력 토큰에 비례).
