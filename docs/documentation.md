# 문서 규약

코드의 기준(SSOT)은 두 종류 문서로 관리한다. 결정은 `docs/adr/0001-adr-and-spec-as-ssot.md`.

| 위치 | 담는 것 | 성격 |
|---|---|---|
| `docs/adr/NNNN-<제목>.md` | 왜 이렇게 결정했나 | 불변. 바뀌면 새 ADR로 대체 |
| `docs/specs/<영역>.md` | 지금 어떻게 동작하나 | 코드와 함께 계속 갱신 |

## 규칙

- **ADR을 쓰는 경우:** 되돌리기 어려운 선택. 기술 스택, 데이터 구조, 영역 간 인터페이스, 협업 규칙. 템플릿은 `docs/adr/0000-template.md`, 번호는 마지막 ADR + 1.
- **spec을 쓰는 경우:** 다른 팀원이 의존하는 영역마다 하나. 템플릿은 `docs/specs/_template.md`. 작업 영역을 새로 맡으면 먼저 spec을 만든다.
- **같은 PR에 넣는다:** 동작이나 구조를 바꾸는 PR은 관련 spec(필요하면 ADR)을 그 PR에서 함께 갱신한다. PR 템플릿의 문서 항목에 체크한다.
- **소유자 없음:** 누구나 어느 문서든 고친다. 의견이 다르면 PR 리뷰에서 조정한다.
- **파일명:** 영문 소문자, 하이픈 구분. 본문은 한국어.
