# 0001. 설계 결정은 ADR, 현재 동작은 spec으로 기록한다

- 상태: 채택
- 날짜: 2026-11-04

## 배경

팀원이 각자 영역을 따로 작업한 뒤 push하므로, 결정 사항과 현재 동작의 기준(SSOT)이 코드와 대화 기록에 흩어지기 쉽다.

## 결정

- `docs/adr/`: 되돌리기 어려운 설계·구조 결정을 번호순으로 기록한다. 쓰고 나면 수정하지 않고, 바뀌면 새 ADR로 대체한다.
- `docs/specs/`: 영역별로 "지금 어떻게 동작하나"를 한 파일로 유지한다. 코드와 함께 계속 갱신한다.
- 문서 갱신은 해당 변경 PR에 함께 넣고, PR 템플릿의 문서 항목으로 확인한다.
- 문서 소유자는 두지 않는다. 누구나 수정하고 PR 리뷰로 조정한다.

## 이유와 대안

- ADR만: 현재 상태를 알려면 ADR 여러 개를 읽어야 한다.
- spec만: 왜 그렇게 했는지가 PR 설명에만 남아 유실된다.
- RFC 절차: 소규모 팀에 과하다.

## 영향

PR을 올릴 때 관련 spec/ADR을 갱신했는지 한 번 더 확인해야 한다. 규약 전체는 `docs/documentation.md`.
