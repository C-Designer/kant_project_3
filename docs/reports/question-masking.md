## 요약

`/query`가 질문 속 개인정보를 `<전화1>` 같은 자리표시자로 가린 뒤 처리하고, 응답 직전에 원래 값으로 되돌린다. 가린 채로 답하지 못하면 마스킹을 풀고 다시 물을지 안내한다. 사용자가 같은 질문에 `"unmask": true`를 붙여 다시 보내면 원문으로 처리하되, Langfuse 기록에서는 다시 가린다. 검색 자료(문맥)는 가리지 않는다.

변경 파일 중 `src/api/main.py`, `src/platform/tracing.py`는 platform 영역이고 `src/contracts.py`는 공용 계약이라 리드 확인이 필요하다.

## 왜 필요한가

- 발제 금지 사항: "API 키와 개인정보를 저장소, 로그, 발표 화면에 남기지 않는다"(requirements.md 163·169행).
- 지금은 질문 원문이 외부 LLM(답변 생성, 하위 질문 분해), 공용 Langfuse 트레이스, JSONL 기록에 그대로 간다.
- 사용자가 입력하는 것은 질문뿐이다. 검색 자료는 교육용 가상 자료라 가리지 않는다.

### 결정

1. **범위.** ADR 0002가 `masking` 영역을 "개인정보 없으면 해당 없음"으로 지웠다. 이번 변경은 새 영역을 만들지 않고 answer(규칙)와 platform(연결)에 넣었다. 새 ADR(0006)로 남길지 정해 달라.
2. **기록 규칙 해석.** requirements.md 158행은 "질문 원문, 실제 모델 입출력"을 남기라고 하고, 163·169행은 개인정보를 기록하지 말라고 한다. 기본 요청은 모델이 받은 것도 가린 질문이라 둘이 충돌하지 않는다. 동의한 재질문은 트레이스에 남는 모델 입력이 실제와 다르다. 제안: 금지 사항이 우선한다.
3. **동의 후 기록.** 사용자의 동의는 "외부 모델에 보내도 된다"는 것이고 기록 금지는 발제 규칙이라 풀리지 않는다고 봤다. 제안: 동의해도 기록은 가린다(구현됨).
4. **자료에 실린 업무용 이메일.** Basic PDF 15개 모두에 이메일이 있다(352건, `booking@…` 같은 업무 주소). 사용자가 이 주소를 질문에 쓰면 가려져서 모델이 자료의 주소와 같은지 대조하지 못한다. 제안: 그대로 두고 재질문으로 회복한다. 대안은 자료에 나온 주소를 제외하는 것(search와 협의 필요)이다.
5. **PR 단위.** 마스킹·복원(1단계)과 재질문·계약·tracing(1b)을 PR 두 개로 나눌지, 하나로 올릴지.
6. **범위 밖.** Langfuse `user_id`(로그인 이메일의 `@` 앞부분)는 이번 변경으로 바뀌지 않는다. 필요하면 별도 Issue.

## 동작

기본 요청:

1. `/query`가 질문을 받는다. 원문은 이 핸들러 안에만 있다.
2. `masking.mask()`가 질문을 가리고 대응표(`{<전화1>: 원래 값}`)를 만든다.
3. `run_query(가린 질문)`. 트레이스·검색·LLM·JSONL은 가린 질문만 받는다.
4. `masking.restore()`가 `answer`·`reason`의 자리표시자를 되돌린다.
5. 가린 값이 있는데 `needs_clarification`·`abstained`이면 `unmask_offer`에 안내를 싣는다. `answered`·`error`는 싣지 않는다.

동의한 재질문:

1. 클라이언트가 같은 질문에 `"unmask": true`를 붙여 보낸다. 서버는 첫 요청의 질문을 보관하지 않는다.
2. `tracing.hide_pii()` 안에서 `run_query(원문)`. 모델은 원문을 받고, Langfuse에 기록되는 입력·출력·메타데이터는 규칙으로 다시 가린다.
3. 이 요청에는 다시 안내하지 않는다.

## 마스킹 대상

| 가리는 것 | 조건 |
|---|---|
| 주민번호, 카드번호, 면허번호, 이메일, 휴대폰, SNS 주소, 나이 | 항상 |
| 유선 전화 | 구분자가 있을 때만(`02-123-4567`) |
| @아이디, 계좌, 여권번호, 생년월일, 성별 | 단서어 뒤에서만(`인스타 @…`, `계좌 …`, `여권 …`, `생일 …`, `저는 … 여성`) |

일부러 가리지 않는 값(테스트로 고정): 컨테이너 번호(`MSKU1234567`), 운임·날짜, 붙여 쓴 HS 코드(`0201100000`), 대표번호(`1588-…`), 단서어 없는 예약번호, `@20ft`, `여성의류`, `3세대`·`3세트`·`21세기`.

알고 있는 한계:

- 이름·직장·주소·민감 정보(의료·재무·법적·정치·종교 등)는 정규식으로 못 잡아 아직 가리지 않는다.
- 13자리 바코드(880…)는 주민번호 모양이라 가려진다. 주민번호가 새는 쪽이 더 나빠서 이렇게 정했다.
- "만 35세 이상 할인" 같은 조건 값도 나이로 가려진다. 답을 못 하면 재질문으로 회복된다.

## 확인하지 않은 것

- 실제 Langfuse 서버에서 재질문 요청의 트레이스가 가려지는지. 테스트는 추적을 끈 상태에서 mask 함수만 확인했다.
- `gpt-6-luna`가 자리표시자를 그대로 옮겨 쓰는지, 가린 질문 때문에 되묻기·보류가 늘어나는지.
- 자리표시자가 BM25·임베딩 검색 결과에 주는 영향.
- Intermediate·Advanced 자료 PDF의 개인정보 모양 값(Basic만 셌다).
