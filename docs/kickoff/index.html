처음 보는 말 풀이

말뜻
영역한 사람이 책임지는 품질의 묶음. search(검색) · answer(답변) · metrics(실험 자동화) · judge(채점) · platform(뼈대·기록·운영). 폴더 src/<영역>/과 1:1
뼈대리드가 11/6 오전까지 머지하는 최소 동작 코드. 질문 1개가 naive 검색으로 답까지 나오고 Langfuse에 기록되는 상태. 다들 이 위에서 자기 영역을 판다
specdocs/specs/<영역>.md. 내 영역이 지금 어떻게 동작하는지 적은 문서. "미정"을 값으로 채우는 것이 첫 작업
ADRdocs/adr/. 되돌리기 어려운 결정을 왜 했는지 적은 문서. 한 번 쓰면 안 고치고, 바뀌면 새 번호로 쓴다
contracts.py영역끼리 주고받는 데이터의 모양을 코드로 정한 파일. 여기를 바꾸면 PR 제목에 [interface]를 붙이고 짝에게 먼저 알린다
config.py · 동결k, 토큰 한도, 모델, timeout 같은 공통 설정을 한 파일에. 11/10 아침에 잠그고(동결), 그 뒤로는 바꾸지 않는다. 바꾸면 실험 전부 재실행
짝데이터를 직접 주고받는 두 영역. search↔answer, metrics↔judge, platform↔metrics. 바꾸기 전에 서로 알려준다
run_query()질문 하나를 검색 → 답변 → 기록까지 처리하는 함수. API도 실험 러너도 이것을 부른다
RunRecord · EvalRecord질문 하나 × 검색 방식 하나의 실행 결과 한 줄, 그리고 그에 대한 채점 결과 한 줄. metrics가 앞을 만들고 judge가 뒤를 만든다
Langfuse · request_id질문마다 번호표(request_id)를 붙여 검색 결과·모델 입출력·시간·토큰을 한 화면에서 따라갈 수 있게 남기는 도구. 발제 필수
Hit@k · Recall@k검색이 정답 문서를 하나라도 찾았나(Hit), 몇 개나 찾았나(Recall). k = 답 만들 때 쓴 상위 조각 수
RAGAS Faithfulness · Judge 4항목답이 찾아온 자료에 근거했나(Faithfulness), 그리고 사실·조건·근거·판단이 각각 맞나(Judge, 0/1). 둘을 합산하지 않는다
null (해당 없음 / 평가 불가)점수를 매길 대상이 없거나 채점이 실패한 경우. 0으로 바꾸지 않고 평균에서 뺀다
룰셋 · CODEOWNERSGitHub 설정. main에 직접 push를 막고, 리드 승인이 없으면 머지 버튼이 안 열린다
Squash and mergePR의 커밋 여러 개를 하나로 합쳐 main에 넣는 방식. 리드만 한다. 머지 뒤 로컬 브랜치는 git branch -D로 지운다
M0 ~ M6날짜별 마일스톤. M1 뼈대(11/6) · M3 동결·전체 실행(11/10) · M6 제출(11/13)이 GitHub 마일스톤으로 등록돼 있다. 발표본까지 전부 M5(11/12)에 끝내고 금요일은 리허설과 제출만
