5. 내 하루 (Issue 하나 기준)

아침에 보드를 본다

"담당별" 탭에서 내 카드 중 Todo 하나를 고른다. 카드를 열면 Issue 본문이 보인다. 할 일·완료 조건·기준 문서를 읽는다. 카드는 Todo에 그대로 둬도 된다(PR을 올리고 본문에 Closes #번호가 있으면 In Progress로 옮겨진다. 안 움직이면 "보드" 탭에서 직접 끌어다 놓는다).

최신 main에서 브랜치를 만든다

main이 어제보다 바뀌었을 수 있으니 항상 pull부터.

git switch main
git pull
git switch -c feat/chunking      # type/짧은-설명. 영문 소문자, 하이픈
작업하고 커밋한다

에이전트(Claude Code, Codex)로 해도 된다. 단, 내가 설명할 수 있는 코드만. 커밋 메시지는 PR 제목과 같은 형식.

git add src/search/chunking.py docs/specs/search.md
git commit -m "feat: 청킹 v1, 표·단위·적용일 보존"
git push -u origin feat/chunking
PR을 올린다 (웹이 쉽다)

push 직후 저장소 첫 화면에 노란 띠 "Compare & pull request"가 뜬다. 안 보이면 Pull requests 탭 → New pull request → compare를 내 브랜치로. 본문 칸에 템플릿이 자동으로 들어오니 채우고, 맨 아래 Closes #13. 캡처는 본문 입력창에 이미지를 드래그하거나 붙여넣으면 링크가 자동으로 생긴다.

명령줄로 하려면 (본문은 6절 예시를 레포 밖 파일, 예: ~/pr.md에 써 둔다. 이미지는 PR 페이지에서 본문 오른쪽 ··· → Edit로 붙인다):

gh pr create --title "feat: 청킹 v1, 표·단위·적용일 보존" --body-file ~/pr.md

gh pr create --fill은 쓰지 않는다(템플릿이 사라진다).

카드를 Review로 옮긴다

보드 상단 탭을 "보드"로 바꾸고 내 카드를 Review 칸으로 드래그한다(또는 카드 클릭 → 오른쪽 패널 Status → Review). 이것만 자동이 아니다. 이 칸에 있으면 "리드가 봐 주세요"라는 뜻.

리드가 보고 머지한다

리드가 보는 4가지: ① 돌아가나(본문의 명령·캡처) ② spec·contracts와 맞나, spec도 고쳤나 ③ 키·개인정보·data/ 없나 ④ 내가 설명할 수 있나. 스타일·네이밍은 메모만 남기고 막지 않는다.

머지되면 정리한다

원격 브랜치와 Issue는 알아서 정리된다. 로컬만 지운다. Squash 머지라 -d가 아니라 -D.

git switch main
git pull
git branch -D feat/chunking

7. 리뷰에서 수정 요청이 오면

같은 브랜치에서 고치고 push하면 PR에 자동으로 올라간다. 새 PR을 만들지 않는다. push하면 이전 승인이 사라지므로, PR 페이지 오른쪽 Reviewers의 C-Designer 옆 ↻(Re-request review)를 누르고 Slack proj_3rd에 한 줄 남긴다. 카드가 Review 칸 밖으로 나가 있으면 다시 Review로.

git add <고친 파일>
git commit -m "fix: 리뷰 반영, 각주가 끊기던 청크 수정"
git push

8. main이 먼저 바뀌어서 충돌이 나면

PR 화면에 "This branch has conflicts"가 뜨면 올린 사람이 자기 브랜치에서 푼다. 남의 브랜치에는 push하지 않는다.

git switch feat/chunking       # 내 브랜치에서
git fetch origin
git merge origin/main          # 충돌 난 파일을 열어 <<<< ==== >>>> 를 정리. VS Code면 Accept Current/Incoming 버튼
git add <정리한 파일>
git commit --no-edit           # 편집기 안 열고 기본 메시지로 커밋
git push

10. 에이전트(Claude Code · Codex)로 작업할 때

  • 레포의 CLAUDE.md·AGENTS.md가 규칙을 알려주므로 에이전트도 같은 순서로 문서를 읽는다. 다른 영역 폴더는 고치지 말라고 돼 있다.
  • 에이전트가 PR을 만들 때는 템플릿을 채운 본문을 --title, --body로 넘기게 한다.
  • 머지 전에 내가 그 코드를 발표에서 설명할 수 있어야 한다. 설명 못 하면 머지하지 않는다(체크 ④).
