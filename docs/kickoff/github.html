일을 받아서 main에 넣는 순서

할 일 하나는 Issue 하나, 바꾼 것 한 묶음은 PR 하나, main에 넣는 것은 리드만. Project 보드는 그 상태를 보여주는 창이다. 2026-11-05 기준 Issue 40개가 전부 열려 있고, 머지된 PR 8개는 모두 리드가 올린 문서 PR이다.

1. 카드 하나가 보드를 지나가는 길

2. GitHub이 대신 막아주는 것과 우리가 지키기로 한 것

룰셋 main-protection이 강제

금지대신
main 직접 push (리드도)브랜치 → PR
main force push · 삭제revert PR
승인 1 + 코드오너(@C-Designer) 승인 없이 머지리드가 리뷰·승인·머지. 본인 PR은 룰셋 우회
새 push 후 이전 승인 유지재승인

필수 status check는 없다(CI 없음). 그래서 PR 본문의 실행 증거가 CI 역할을 한다.

팀 규칙 (GitHub은 못 막음)

  • 머지는 리드만. 승인 뒤 다른 사람이 버튼을 누르지 않는다
  • PR 하나에 목적 하나. 반나절 단위. 하루 넘게 쌓이면 쪼갠다
  • 브랜치 <type>/<짧은-설명>, 커밋·PR 제목 <type>: <설명>. type: feat fix refactor docs test chore
  • [interface]: contracts.py·config.py 변경은 제목에 붙이고 짝에게 먼저 알림. 라벨 interface
  • 리드가 안 보는 것: 스타일, 네이밍, 리팩터 제안. 메모만 남기고 막지 않는다
  • 11/12 이후: 버그 수정 PR만
  • 남의 브랜치에 push하지 않는다. 충돌은 올린 사람이 git merge origin/main으로
